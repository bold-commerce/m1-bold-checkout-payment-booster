# Bold Checkout Payment Booster — Changes (2026-06-03)

**Branch:** `CHK-9603-prevent-duplicates-422-fix`  
**Scope:** Standard `checkout/onepage` only — **no Firecheckout**

This release builds on duplicate-order prevention (2.1.6) and adds client/server Bold session synchronization to fix `422 insufficient_payments_for_order_balance` on `payments/auth/full`.

---

## Summary

| Area | Change |
|------|--------|
| **422 fix** | `getCheckoutSession` endpoint + client sync before Payments SDK init; `initBoldCheckoutData` before hydrate at `saveOrder` |
| **Rotation handling** | Log `public_order_id` rotation; clear wallet EPS session when Bold order is re-created |
| **Security** | EPS wallet binding on `saveOrder`; exact EPS order lookup; IndexController POST + Ajax hardening |
| **Layout** | Removed `firecheckout_index_index` handle from module layout (main-only branch) |

---

## Backend

- **`controllers/IndexController.php`**
  - New `getCheckoutSessionAction` (POST + Ajax + form key → current tokens).
  - `getCartData`, `getCartTotals`, `getCartItems` require POST + Ajax + form key.

- **`Block/Payment/Form/Base.php`**
  - `getCheckoutSessionPayload()` for Ajax response.
  - `getWalletCheckoutJsConfig()` includes `getCheckoutSessionUrl`.

- **`Service/Bold.php`**
  - Logs when `public_order_id` rotates after failed resume.
  - Clears registered wallet EPS id on rotation.

- **`Observer/CheckoutObserver.php`**
  - Calls `initBoldCheckoutData($quote)` before `Hydrate::hydrate()` in `beforeSaveOrder`.

- **`Service/Order/PlacementGuard.php`**
  - `assertWalletEpsOrderIdBelongsToSession` on predispatch and `assertQuoteCanSubmit`.
  - Exact serialized EPS value lookup in `findOrderByEpsOrderId`.

- **`Service/Order/CheckoutSessionOwnership.php`**
  - `clearWalletEpsOrderId()` for rotation cleanup.

---

## Frontend

- **`design/.../base.phtml`**
  - `syncCheckoutSessionFromServer`, `applyCheckoutSessionPayload`, `resetBoldPaymentsInstance`.
  - Sync runs in `getBoldPaymentsInstance()` only (no Firecheckout observers).
  - `trace_id` and SCA use `this.publicOrderId` (not page-load PHP values).
  - `getCartData` uses POST + form key.

- **`skin/.../expresspay.js`**
  - `getCartTotals` / `getCartItems` send `X-Requested-With: XMLHttpRequest`.

- **`design/.../layout/bold/checkout.xml`**
  - One-page handle only; Firecheckout handle removed.
