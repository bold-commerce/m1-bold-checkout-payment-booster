Without PlacementGuard Duplicate risk

Typical failure mode: double-click, FireCheckout reload, or multiple SPI listeners → parallel saveOrder.

Typical outcomes (no guard)

  • Two or more Magento orders for one checkout session
  • Customer charged twice or conflicting order state
  • Race on bold_checkout_payment_booster_order public_id (logged if caught in afterSaveOrder)
  • No “already being placed” message — errors are inconsistent

With PlacementGuard Protected

SaveOrderObserver::predispatchSaveOrder runs before the controller; second requests are blocked or redirected to the existing order.

1 — Shopper
Place order Same frontend path (tokenize → saveOrder)
↓
2 — First saveOrder request
Predispatch: evaluatePlacementRequest() Payment method is Bold / Fastlane only
↓
Allow Session flag bold_order_placement_in_progress = 1
MySQL GET_LOCK(bold_checkout_place_…) for public_id
↓
Magento saveOrder proceeds beforeSaveOrder → assertQuoteCanSubmit() (2nd line of defence)
↓
Single order created + Bold mapping saved afterSaveOrder → public_id → Magento order id
↓
Postdispatch: cleanupAfterSaveOrder() Clears session flag; RELEASE_LOCK
↓
JSON success → redirect to checkout success
3 — Concurrent duplicate request
Predispatch: evaluate again
↓
Flag still set OR lock held block_in_progress
Order already exists for public_id success_existing
↓
Exception shown to user “Your order is already being placed. Please wait.”
JSON redirect to success Same order — no second Magento order

Typical outcomes (with guard)

  • At most one Magento order per Bold public_id / placement window
  • Duplicate clicks get a clear wait message or success redirect
  • Duplicate attempts logged to bold_checkout_payment_booster_duplicate_order.log
  • Frontend still benefits from single SPI runtime + tokenize cooldown (separate concern)

PlacementGuard::evaluatePlacementRequest() — decision tree (Bold payment only)

Quote missing? → block (“cart could not be found”)
Quote inactive + order exists for quote? → success_existing (redirect)
Session bold_order_placement_in_progress? → block_in_progress (“already being placed…”)
public_id already mapped to order? → success_existing + log duplicate attempt
Cannot acquire MySQL lock for public_id? → block_in_progress (“already being placed…”)
EPS order_id already used? → success_existing
Otherwise → set session flag, return allow → Magento saveOrder runs

    participant U as Shopper
    participant FE as base.phtml
    participant G as PlacementGuard

    participant B as Bold Auth API

    FE->>M: saveOrder (1st)
    M->>G: predispatch evaluate
    G->>G: SET flag + GET_LOCK
    G-->>M: allow
    M->>B: Authorize
    M-->>U: Order created
    M->>G: postdispatch cleanup
    G->>G: CLEAR flag + RELEASE_LOCK

    FE->>M: saveOrder (2nd)
    M->>G: predispatch evaluate
    G-->>M: block_in_progress
    M-->>U: "Your order is already being placed. Please wait."
